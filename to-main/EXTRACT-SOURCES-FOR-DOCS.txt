MACHINE-READ PARTS OF THE RULE DOCUMENTS
========================================

What this is: a list of every line in the rule documents that a script reads, for each document that a data/extracted/*.json extract (or the attacks.json pair) is built from. Anything not listed under a document is not read by that document's generator. Docs may edit those other lines freely, with the cautions given under each document.

How it was made: by reading the generator scripts in scripts/ at the MAIN_WORK HEAD, commit 20f86f98. "script L123" is a line in the named generator. "doc L123" is a line in the document at that commit. Line numbers move when lines are added above them, so read them as "where it is today".

Which generator builds which extract is taken from the HOW table in scripts/check_extracts.py (L135-184).

For Docs, from CODER (MAIN, PT-2752, 2026-11-08, ruled b): a table row in any document below, and the attack rows of ATTACKS-04 to -07, is out of Docs' lane. Send the change through MAIN; CODER applies it to the document and the data together. Prose that no generator reads stays Docs' to edit; flag every edit to a document on this list.
Since it was made: design/EVENT-KINDS-01.md gained one row (table.difficulty-set, CODER, 2026-11-08), so its line numbers after that row are one later.


GENERAL RULES (they apply to every document below)
--------------------------------------------------

1. Changing a value changes the extract. A machine-read cell or line is copied into JSON, often word for word. Rewording it, even with the same meaning, changes the extract's content. The docs-profile gate blocks on that (check_extracts.py L124-132). Only the source md5, the line counts and the ".md:N" line references count as provenance. A line shift caused by adding prose above a row only warns.

2. The shared table reader (scripts/_tables.py) is used by most generators.
   - clean() (L11-12) removes * ` ⚠ ✓ from a cell. Bold, italics, backticks and warning or check glyphs in a cell are therefore usually NOT data. Exceptions are noted per document: extract_powers keeps ⚠, and several readers match on ** bold markers in the raw line.
   - table_at(heading regex, header=) (L38-61) finds the first line matching the heading regex. From there it takes the first table, meaning a "|" header row immediately followed by a |---| separator. If header= is given, the table's leading header cells must match. It does NOT stop at the end of the section when searching.
   - rows() (L17-36) reads every "|" line after the separator. Separators are skipped. Non-"|" lines (prose, blockquotes, blank lines) are skipped and the table resumes at the next "|" line. Reading stops ONLY at a line starting with "#" or a line that is exactly "---".
   - CONSEQUENCE FOR DOCS. Prose between rows is safe. But any new "|" line placed after a read table and before the next heading or "---" is read as a row of that table. That includes a second, unrelated table and its header row. To add a table near a read table, put a heading or a "---" line between them. Adding a heading or "---" in the middle of a table that is interrupted by prose cuts the table short there.

3. Header row text is load-bearing where a generator matches on it, and is quoted below as written. Header cells are compared after clean() and lower-casing, so ⚠ and bold on header words are not load-bearing. The words are.

4. An em dash "—" in a cell usually means "none" and becomes null. Do not replace one with words, or with a blank where the cell count is fixed.

   - Group headings (script L46-49): every line starting "### " sets the group. The group is the heading text up to the first "—", after clean().    - Not read: prose, blockquotes, rows whose cell 1 does not look like a kind (sub-heading rows inside tables), the table at L318, and anything before the first "### ".
